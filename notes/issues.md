# 課題一覧

## #1 読み上げ順：横並びの図形（タイムライン・表形式）を行ごとに読んでしまう【対応済み 2026-09-23】

- 報告：2026-09-23（Phase 1 の確認中、日付と説明が横に並ぶタイムラインのスライド）
- 症状：日付 4 つを先に全部読み、その後で各日付の説明を読む。
  - 期待：`日付1 → 説明1 → 日付2 → 説明2 → …`
  - 実際：`日付1 → 日付2 → 日付3 → 日付4 → 説明1 → …`
- 原因：`src/lib/pptx.js` の `slideParagraphsInReadingOrder` は、図形を「上→下、同じ行なら左→右」の行単位で並べている。日付と説明が別々のテキストボックスで、日付どうしが同じ高さにあるため、日付の行がまとめて先に読まれる。Phase 0 で既知の制約とした「左右 2 段組」と同じ原因。
- 対応案：図形を横方向の位置で「列」にまとめ、列が 2 つ以上あり、それぞれに上下に並んだ図形があるときは、列ごとに上から読む（列優先）。
  - 列のまとめ方：タイトル以外の図形について、横方向の範囲（`a:off x` 〜 `x + a:ext cx`）が重なるものを同じ列とみなす。
  - スライド全体の幅にわたる図形（リード文など）は列に含めず、行の順で前後に置く。
  - 画面の文字から読む場合（`slides-page.js` の `domSlideText`）も同じ方針にそろえる。
- 確認方法：このスライドのほか、左右 2 段組、表のようなグリッド、1 段組の通常スライドで順番が崩れないこと。

## #2 行の途中の改行で文が途切れる【対応済み 2026-09-23】

- 報告：2026-09-23（同じスライド）
- 症状：「新システム」と「による運用のみ」のように、改行の前後が別々の文として読まれ、間が空く。
- 原因：テキストボックス内の手動改行（`a:br` や `Shift+Enter`）を、`src/lib/speech-text.js` の `toUtterances` が発話の区切りとして扱っている。見た目を整えるための改行でも文が分かれてしまう。
- 対応案：同じ段落内の改行は発話の区切りにせず、つないで読む。日本語どうしは詰めてつなぎ、英数字どうしは空白でつなぐ。文の区切りは文末（。！？）と段落の区切りだけにする。
  - 箇条書きのように改行で項目を並べている場合は、行頭に記号や番号があれば区切りとして残す。

## 対応内容（#1・#2）

- `src/lib/reading-order.js` を追加し、pptx と画面の文字の両方で同じ並べ方を使うようにした。
  高さで行に分け、各行を横の位置で列に分ける。続く行が同じ列の並びならまとめ、列ごとに上から読む。
  テキストボックスは隣と少し重なりがちなので、重なりが狭い方の幅の 25% 以下なら別の列とみなす。
- `src/lib/speech-text.js`：改行が Enter か Shift+Enter かは判断できないため、文の形で判断する。
  同じ図形の中で、前の行が読点で終わる、または次の行がひらがな・英小文字で始まるときはつなぐ。
  行頭が箇条書きの記号や番号なら区切る。図形をまたいではつながない。
- 保存結果の形式を v2 に上げ、古い保存結果は自動で取り直す。
- 合成スライドで確認：タイムライン、左右 2 段組、1 段組（見出しが最後）、全幅のリード文＋3 列。

### 残る制約
- カードを格子状に並べたスライドは列ごとに読む（1→3→2→4）。
- 「本番」＋「運用の開始」のように漢字で終わり漢字で始まる改行は、文の途中でもつながない（「操作マニュアルの公開」＋「試験運用の開始」と見分けられないため）。

## #3 語の強調表示が声と少しずれる【保留・低優先】

- 報告：2026-09-27（Phase 4 の確認、Kyoko）。「若干ずれるが、違和感は大きくない。完全には一致しない」
- 考えられる原因（未調査）：
  1. 語の区切りの違い：macOS の声が送る語の範囲（`length`）が届かない場合は `Intl.Segmenter` で語の終わりを求めているため、声の区切りと一致しないことがある
  2. 合図の時刻：`word` イベントは、声がその語を読み始める時点ちょうどではなく、少し前後して届くことがある
  3. 読み方の整形の違い：括弧・記号・英単語などを、声は画面の文字と違う単位で読むことがある
- 調べ方の案：1 文分の `word` イベント（`charIndex`、`length`、届いた時刻）をサイドパネルに記録して表示し、実際の声と見比べる。ずれが「早い／遅い」「語の長さが違う」のどれかで対策が変わる
  （早い・遅い → 表示を一定時間ずらす。長さが違う → 声が送る `length` を優先し、区切りの求め方を変える）
