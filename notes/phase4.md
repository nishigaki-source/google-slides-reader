# Phase 4：読んでいる語の強調表示

## 仕組み

- `chrome.tts` の `word` イベントの `charIndex`（と、届けば `length`）で、読み上げ中の語を `<mark>` で強調する。文単位の強調（枠）はこれまでどおり。
- `length` が届かない声では、`Intl.Segmenter('ja', { granularity: 'word' })` で語の終わりを求める（`speech.wordEnd`）。
- 辞書で置き換えた文を読んでいるときは、`charIndex` が置き換え後の文の位置になる。`speech.applyDictionaryMapped` が置き換え前後の位置の対応表を作り、画面の文字の位置に戻す。置き換えた語の途中を指す場合は、置き換え前の語全体を強調する（例：「ピーダブリューエー」を読んでいる間は「PWA」全体）。
- 設定「読んでいる語を強調する」（既定はオン）。`word` イベントが届かない声（Google 日本語）では文単位の強調だけになる。

## 確認

- 自動テスト：位置の対応付け（辞書あり・なし）、語の終わり（長さあり・なし）。`npm test` で 16 件。
- ヘッドレス Chrome で、`word` イベントを模した状態の表示を確認した（「PWA」を辞書で置き換えて読んでいる間、画面の「PWA」が強調される）。

## 確認項目（利用者の Chrome）

- [ ] Kyoko で再生すると、読んでいる語が強調され、声と合っている
- [ ] 辞書で置き換えた語を読んでいる間、元の語が強調される
- [ ] 設定をオフにすると、文単位の強調だけになる
