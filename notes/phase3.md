# Phase 3：取得の高速化と自動テスト

## 背景

pptx の書き出しは、実際の資料（12 枚）で 37〜61 秒かかった。取得が終わるまでは画面の文字で読めるが、スライドショー中はノートを読めなかった。

## 分かったこと（2026-09-27、公開サンプルで調査）

### 編集画面：`DOCS_modelChunk`

ページの `<script>` に `var modelChunk = {"chunk": [...], "revision": N};` が、スライドごとに入っている。中身は資料を組み立てる編集コマンドの列。

| コマンド | 形 | 意味 |
|---|---|---|
| 12 | `[12, ページID, 何枚目, 種類, …]` | ページ。種類 0 = スライド、1 = レイアウト、2 = マスター |
| 3 | `[3, 図形ID, 図形の種類, [sx, shy, shx, sy, tx, ty], 属性, 親]` | 図形。親はページ ID（グループの中ならグループ ID） |
| 15 | `[15, 図形ID, セル, 位置, 文字]` | 文字の挿入。改行は `\n`、段落内の改行は `\u000b` |

- ノートは `<スライドID>:notes` というページの上にある図形。
- 属性は `[キー, 値, …]` の並び。キー 54 がプレースホルダーの種別で、Slides API の PlaceholderType と同じ番号（1 = 本文、4 = 中央のタイトル、6 = 日付、12 = スライド番号、13 = サブタイトル、15 = タイトル、16 = スライドの画像）。
- 座標の単位は EMU の 1/25（スライドの横幅 365760 = 9144000 EMU）。図形の基準の大きさは 100000 で、画像はキー 8 と 9 の画素数が基準。
- 公開サンプルでは、pptx から取ったときと同じ本文とノートが 1 ミリ秒で得られた。

### /present：`viewerData.docData`

`var viewerData = {… docData: [[横幅, 高さ], [[スライドID, 何枚目, …, ノートのHTML(9番目), …], …], …]}`。
ノートは HTML で、段落内の改行は U+FFFD。**本文は入っていない**（本文は画面の `aria-label` から読む）。

## 実装

- `src/lib/page-data.js`：`deckFromModel`（編集画面）と `notesFromViewer`（/present）。読めなければ null を返す。
- `content.js` の優先順：ページのデータ → 保存結果 → pptx。ページのデータは保存もしておき、あとで /present を開いたときに使う。
  - 埋め込みのスライド数がフィルムストリップの枚数より少なければ、一部しか入っていないとみなして使わない。
  - 「取り直す」ボタンは pptx を使う（ページを開いた後の編集も反映するため）。
- サイドパネルの表示：ページのデータなら「読み込み済み（12枚）」、pptx なら「取得済み（12枚・N分前）」。

## 自動テスト

`npm test`（node:test）。13 件。

- `tests/reading-order.test.js`：タイムライン、2 段組、1 段組（見出しが最後）、リード文＋3 列、スライド番号・日付の除外
- `tests/speech-text.test.js`：文の分割、改行のつなぎ、長文の分割、辞書
- `tests/page-data.test.js`：公開サンプルの埋め込みデータ（`tests/fixtures/`）からの取り出し、壊れたデータ
